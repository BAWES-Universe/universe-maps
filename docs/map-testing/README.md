## Recording results

Each card has the original eight review fields and a blank dated test block. Use Pass / Fail / Not tested / N/A for test results. Include exact map revision, engine commit, actual session URL, tester, date, device and evidence. Keep design decisions (Approve / Tweak / Reject / Pending) separate from technical test results.

Unchecked boxes are proposed work, not failures. Historical source evidence is retained verbatim, with its original scope. No new live checks were run merely by producing this register.

## Maintenance

Edit the Markdown cards directly for human review. For a new map revision, add a separately identified entry or dated block; do not overwrite a prior revision’s approval or reported failure. Update the JSON register only when identity/path metadata changes, and retain the immutable workbook import as provenance. Before advertising a play link, verify the deployed map/engine revision and that the intended user can open it.
